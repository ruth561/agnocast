## Description

Adds the shared building blocks for two upcoming features — cross-IPC-namespace / cross-ECU observability (#1351) and cross-IPC-namespace bridge auto-generation (#1352 + #1353):

- **`ros2agnocast_discovery_msgs`** package — three msgs (`AgnocastEndpoint`, `AgnocastTopic`, `AgnocastDaemonState`) describing the full Agnocast state of one IPC namespace at one timestamp.
- **`ros2agnocast_discovery_agent`** package — Python rclpy node (one process per IPC namespace) that snapshots the local Agnocast state via the existing `libagnocast_ioctl_wrapper.so` and publishes it on `/_agnocast_discovery` every 1 s with QoS `Reliable + TransientLocal + KeepLast(1) + Liveliness Automatic 30 s`.

The agent is intentionally a thin Python node so reviewers can verify it line-by-line without C++ template machinery; the CLI verb extension (#1351) and the bridge-generation feature (#1352 agnocastlib data layer + #1353 discovery agent: connect everything) build on this base.

This PR is **additive only** — it does not touch `agnocastlib`, heaphook, or the kernel module.

## Notes for reviewers

### Manual test: cross-IPC-namespace observability

> **Caveat**: This has only been exercised on a single physical machine (two IPC namespaces on the same host via `unshare`). Cross-ECU verification on real hardware is still outstanding.

Single-namespace coverage is already automated above. For real cross-IPC-NS verification (requires `CAP_SYS_ADMIN`, not available in CI), run:

```bash
# Prereqs: agnocast kmod loaded; workspace built; three separate shells.

# --- Shell A: IPC NS "alpha" + a talker. The launch file already includes
#     `discovery_agent.launch.xml`, so the daemon is spawned automatically
#     (one daemon per IPC NS — do NOT also `ros2 run discovery_agent`).
sudo -E unshare --ipc bash -c '
  source /opt/ros/humble/setup.bash && source install/setup.bash
  ros2 launch agnocast_sample_application talker.launch.xml &
  sleep 120; wait
'

# --- Shell B: IPC NS "beta", daemon only (no Agnocast traffic in this NS) ---
sudo -E unshare --ipc bash -c '
  source /opt/ros/humble/setup.bash && source install/setup.bash
  ros2 launch ros2agnocast_discovery_agent discovery_agent.launch.xml &
  sleep 120; wait
'

# --- Shell C: host NS, verify both namespaces are visible on the gossip topic ---
source /opt/ros/humble/setup.bash && source install/setup.bash
# If a stale `ros2 daemon` is running with old PYTHONPATH (started before
# install/setup.bash was sourced), it won't know about the new msg package
# and `ros2 topic echo` will report "invalid message type". Force a fresh
# daemon under this shell's env.
ros2 daemon stop && sleep 1 && ros2 daemon start && sleep 3
# Expect two AgnocastDaemonState publishers, one per IPC NS.
ros2 topic info /_agnocast_discovery --verbose | grep "Publisher count"
# The gossip publisher uses Reliable + TransientLocal QoS, so `ros2 topic echo`
# needs matching QoS flags or the subscription's defaults (BestEffort + Volatile)
# will silently fail to match on `durability`. Use `--once` to grab the
# late-joiner snapshot via TransientLocal in one shot.
ros2 topic echo --once \
  --qos-reliability reliable \
  --qos-durability transient_local \
  /_agnocast_discovery
```

> **Caveats**:
> - `sudo -E` is required so that `sudo` preserves `RMW_IMPLEMENTATION` (and other ROS env vars) into the unshared bash. Without `-E`, the inner daemon falls back to the default RMW (Fast-DDS on most systems) while the host shell uses Cyclone DDS — DDS discovery still succeeds via the standard RTPS UDP path so `topic info` shows the publishers, but data delivery between the mixed RMW implementations is unreliable and `topic echo` silently receives nothing.
> - The `ros2 daemon stop && start` step is needed once per fresh shell, after sourcing `install/setup.bash`, so the cli daemon picks up the new `ros2agnocast_discovery_msgs` package in its PYTHONPATH (otherwise `topic echo` rejects the resolved type as "invalid").

Expected:

- Two publishers on `/_agnocast_discovery` (one per IPC NS).
- The alpha snapshot lists `/talker_node` under `topics[]`; the beta snapshot lists nothing under `topics[]` (no Agnocast process in beta).
- Both snapshots share `host_uuid` (same machine) but differ in `ipc_ns_inode`.

### Known design deviation (acceptable; documented here so reviewers don't need to flag it)

- **Publish strategy: 1 Hz timer-only**, not the design's "change-detection immediate publish + 0.1 Hz heartbeat". Worst-case detection latency is therefore ≤ 1 s instead of ~ms; the change-detection optimization is a follow-up.

This PR is two **new** ROS 2 packages plus a tiny Python wrapper around an already-shipped `libagnocast_ioctl_wrapper.so` symbol. No changes to `agnocastlib`, heaphook, kmod, MQ payloads, or any existing ABI. See CONTRIBUTING.md §"Versioning rules".
